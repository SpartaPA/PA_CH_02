# [23강. 카메라 좌표계 변환 심화 (World/Camera/Image/Pixel·Extrinsic/Intrinsic)]
- 모듈: ④ 2D/3D 공간 인지 및 비전 AI
- 한 줄 요약: World → Camera → 정규화 이미지 평면 → Pixel 사슬을 정방향 `project()`·역방향 `backproject()`로 구현하고, 왕복 결과가 원래 점과 일치하는지 `assert`로 검증

## [핵심 개념]
- 좌표 사슬 4단계
  - World: 로봇·환경 기준의 3D 좌표 $P_w$
  - Camera: 외부파라미터 $(R,t)$ 적용 $P_c=RP_w+t$
  - 정규화 이미지 평면: 깊이로 나눔 $(x_n,y_n)=(X_c/Z_c,\;Y_c/Z_c)$
  - Pixel: 내부파라미터 $K$ 적용 $[u,v,1]^\top=K[x_n,y_n,1]^\top$
- 정방향 투영 → 깊이 $Z_c$ 정보 소실(3D → 2D, 광선 하나로 축약)
- 역투영 → 픽셀만으로는 광선만 결정, **깊이 $Z$를 추가로 알아야** 3D 점 복원
  - $x_n=\frac{u-c_x}{f_x},\;y_n=\frac{v-c_y}{f_y}$, $P_c=Z\,[x_n,y_n,1]^\top$
- Camera → World 역변환: $P_w=R^\top(P_c-t)$
  - 회전행렬은 직교행렬이므로 $R^{-1}=R^\top$ (역행렬 계산 불필요)
- 카메라 뒤 점 처리: $Z_c\le0$이면 투영 불가 → `None` 반환
- 좌표 규약 차이
  - OpenCV 카메라 좌표: x 오른쪽, y 아래, z 전방
  - ROS 바디 좌표(REP-103): x 전방, y 왼쪽, z 위 → 두 규약 사이 고정 회전 필요
- 왕복 검증(round-trip test): 정방향·역방향 함수를 짝지어 수치 오차 수준($10^{-9}$)으로 일치하는지 확인 → 변환 방향·전치 실수 조기 발견

## [파일별 내용]
- `01_사슬_왕복_코드로_검증.ipynb` — 교안 3절 "사슬 왕복" 코드 발췌
  - `project(P_w, K, R, t)`: World 점 → 픽셀 `(u, v)`
    - `P_c = R @ P_w + t` 후 `P_c[2] <= 0`이면 `None`
    - `K @ (P_c / P_c[2])`의 앞 두 성분 반환
  - `backproject(u, v, Z, K, R, t)`: 픽셀 + 카메라 좌표계 깊이 `Z` → World 점
    - `K[0,2]`=$c_x$, `K[0,0]`=$f_x$, `K[1,2]`=$c_y$, `K[1,1]`=$f_y$
    - 마지막 줄 `R.T @ (P_c - t)`가 역변환
  - 왕복 검증: `Z=(R @ P_w + t)[2]`로 실제 카메라 깊이를 넘겨 `np.allclose(..., atol=1e-9)`
  - 빠진 맥락: `import numpy as np`, 시험용 `P_w`·`K`·`R`·`t` 정의 없음 → 직접 만들어야 실행 가능
  - 주의: `Z`는 World 기준 거리나 유클리드 거리가 아닌 **카메라 z축 깊이**

## [확인 포인트]
- 기대 결과: `assert` 통과(출력 없음)
- 흔한 실수
  - 역변환을 `R @ (P_c - t)` 또는 `R.T @ P_c - t`로 작성 → 왕복 실패
  - 카메라 뒤 점($Z_c\le0$)을 넣어 `project()`가 `None` 반환 → 언패킹 오류
  - `K[0,1]`(skew)·왜곡계수 무시: 이 코드는 왜곡 없는 이상적 핀홀 가정
- 점검 질문
  - 깊이 $Z$ 대신 카메라 중심까지의 거리 $\|P_c\|$를 넘기면 결과가 어떻게 달라지는가?
  - 왜 픽셀 하나만으로는 3D 점이 하나로 정해지지 않는가?
  - OpenCV 카메라 좌표를 ROS `base_link` 규약으로 바꾸는 회전행렬은?
