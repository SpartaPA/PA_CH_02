## [핵심 개념]
- **Nav2 = 이미 아는 부품의 조립**: Lifecycle Node(Lv.1 15강), 액션(Lv.1 11강), TF 체인(39강), 제어 루프(모듈 ①)
- **전체 구조**
  - 목표 전송(RViz/코드, `NavigateToPose` **액션**) → **BT Navigator**(행동 트리로 전체 지휘)
  - **Planner Server**: 전역 경로
  - **Controller Server**: 지역 제어, `/cmd_vel` 발행
  - **Behavior Server**: 리커버리(후진·회전·대기)
  - **Global/Local Costmap**: 각각 Planner/Controller에 "어디가 위험한가" 공급
  - 전부 Lifecycle Node → **Lifecycle Manager**가 기동 순서 지휘
- **주행 한 사이클**
  - 목표 수신 → 전역 계획(지도 전체, ~1 Hz) → 지역 제어(경로 추종 속도 명령, **20 Hz**, 눈앞 장애물 회피) → 막히면 리커버리 후 재계획
  - 멀티레이트 2층 구조 = **느린 큰 그림 + 빠른 반사신경** (모듈 ①·⑤와 같은 패턴)
- **Global Planner — 격자 위 최단 경로** (정적 지도 + Global Costmap)
  - Dijkstra: 시작점에서 비용의 파도를 모든 방향으로 균등 확장 — 최적 보장, 느림
  - A*: 파도에 목표 방향 휴리스틱(직선거리) 추가 → 같은 최적 경로를 훨씬 적은 탐색 셀로 (NavFn/Smac의 기본 아이디어)
  - 경로는 저비용 셀을 따라 벽에서 떨어져 흐름(인플레이션 효과)
- **Controller(Local Planner) — 눈앞의 운전**
  - 전역 경로는 "어느 길로"일 뿐, 속도·가속 한계와 방금 나타난 장애물은 모름
  - **DWB(Dynamic Window Approach)** 한 주기
    1. 지금 낼 수 있는 $(v,\omega)$ 후보 수십 개 추출 (동적 창 = 현재 속도에서 한 주기 내 도달 가능한 범위, 가속 한계가 울타리)
    2. 각 후보로 짧은 미래 시뮬레이션
    3. 채점(경로 근접·목표 진행·장애물 거리·속도) → 장애물 닿는 후보 탈락, 최고점 명령 발행
  - "후보를 뿌리고 채점해 고른다" = 38강 파티클 필터와 같은 몬테카를로 정신, 44강에서 채점 가중치(critics) 튜닝
- **Costmap — 층을 쌓은 위험도 지도**

  | 층 | 갱신 | 내용 |
  |---|---|---|
  | Static | 로드 시 | 저장 지도(39강)의 벽 |
  | Obstacle | 매 스캔 | 실시간 깊이+추정 포즈로 만든 nvblox ESDF (2D 비교: LaserScan 장애물 층) |
  | Inflation | 위 층 변경 시 | 장애물 주변 비용 부풀림 |

  - 카메라 실습: `nvblox_layer`가 ESDF 슬라이스 공급 + `inflation_layer` 결합 — Nav2가 3D 메시를 직접 탐색하는 것은 아님
- **인플레이션 — 로봇을 점으로 만들기**
  - 로봇은 폭이 있는 물체 → 장애물을 **로봇 반경만큼 부풀려** 계획을 점 문제로 단순화
  - $\text{비용}(d)=\begin{cases}\text{치명}(254) & d<r\ (\text{중심이 오면 충돌 확정})\\ e^{-k(d-r)}\ \text{감쇠} & \text{그 밖 (가까울수록 벌점)}\end{cases}$
  - $d$ 장애물까지 거리 [m], $r$ 로봇 반경 [m], $k$ = `cost_scaling_factor` [1/m], 비용 범위 0~254
  - $k$ 큼 → 벌점이 급히 사라져 대담, $k$ 작음 → 넓게 퍼져 소심
  - `inflation_radius` = 벌점이 미치는 최대 거리 → 너무 크면 좁은 문 양쪽 벌점이 겹쳐 통로가 막힌 것처럼 보임, 하한은 로봇 반지름 + 여유(그 아래는 실제 충돌)
  - 증상 해석: 문 앞에서 머뭇거리다 우회 / 문틀을 아슬아슬 통과 / 벽에 붙어 주행 = 부풀림 크기와 벌점 기울기 설정의 결과
- **Behavior Tree — 왜 상태 머신이 아닌가**
  - "계획→주행→막히면 회전→재계획→후진…" 같은 조건부 재시도를 상태 머신으로 짜면 스파게티(35강 4상태도 전이 6개)
  - BT: 시퀀스/폴백 노드로 "순서대로, 실패하면 대안"을 선언적으로 표현, 로직 변경 = **XML 교체**
  - 기본 트리 뼈대: [Pipeline: 주기적 재계획(`ComputePathToPose`) → 경로 추종(`FollowPath`)] 실패 시 [Fallback: 코스트맵 클리어 → 대기 → 회전 → 후진] 후 본선 복귀
  - 각 리프 = 서버 액션 호출 → **트리가 지휘자, 서버가 연주자**
- **Lifecycle — 기동 순서 지휘**
  - Lifecycle Manager가 의존 순서대로 Nav2 서버 활성화
  - 카메라 실습: cuVSLAM TF·nvblox 비용지도 준비 확인 후 navigation 서버 기동 — cuVSLAM·nvblox를 Nav2 lifecycle 노드로 가정하거나 AMCL을 중복 기동하지 않음
- **(심화) footprint와 전진성 제약**
  - 인플레이션의 "반경"은 원 근사 → 길쭉한 로봇은 **footprint 다각형**으로 방향까지 고려한 충돌 검사(대신 계산 비쌈)
  - 차동 구동(TurtleBot3)은 제자리 회전 가능, 자동차형(Ackermann)은 최소 회전 반경 → **Smac Hybrid-A***가 곡률 제약·전후진 혼합 경로 생성 (Lv.3 조작 계획으로 연결)

## [용어]
- **Nav2**: ROS2 자율주행 스택 — 알고리즘 하나가 아니라 부품들의 조합
- **전역 planner**: 지도 전체를 보고 경로 계획 — 실시간 장애물 대응은 못 함
- **지역 controller**: 눈앞을 보며 속도 명령 생성 — 목적지가 아니라 다음 몇 초를 봄
- **costmap / 층(layer)**: 점유 격자에 위험도 층을 얹은 계획 입력 — 층은 출처별 관리, 사용 시 하나로 합성
- **인플레이션**: 장애물을 반경만큼 부풀리기 — 안전 여유와 통과 가능성의 트레이드오프
- **cmd_vel**: 선속도·각속도 명령, 모든 주행의 최종 출력 — 바퀴별 속도 변환은 그 아래 단계
- **Behavior Tree**: 상황별 행동을 트리로 관리 — 상태 머신과 비슷하나 조합·재사용이 쉬움
- **리커버리 행동**: 막혔을 때 회전·후진·대기 — 발화가 잦으면 튜닝 문제 신호
- **Lifecycle 노드**: 켜짐/준비/활성 상태 관리 — 일반 노드와 달리 상태 전이 명령 필요

## [교안의 실습 과제]
- 코드 블록은 없지만 교안이 직접 해 보라고 제시한 과제
1. **미니 A***: 37강 20×20 격자에 A*(휴리스틱=직선거리) 구현 → Dijkstra와 탐색 셀 수 비교
2. **인플레이션 실험**: 같은 격자에 반경 2셀 치명 + 지수 감쇠 → 감쇠 계수 2종에서 A* 경로가 벽에서 떨어지는 정도 비교 (44강 예습)
3. **미니 DWA**: 점 로봇의 $(v,\omega)$ 후보 21개를 1초 시뮬레이션, 장애물 회피+목표 접근 채점 루프 → 가중치에 따른 과감/소심 운전 관찰
4. **(심화)** 기본 BT XML(`navigate_to_pose_w_replanning_and_recovery.xml`)을 본문 뼈대와 대응시키고, 회전 리커버리를 빼는 수정 위치 표시
