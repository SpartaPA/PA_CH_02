# [45강. [실습] 주행 성공률·소요시간·재계획 측정]
- 모듈: ⑥ SLAM 및 Nav2 자율주행
- 한 줄 요약: 장면 초기화부터 결과 집계까지를 자동 반복하는 벤치마크 러너로 Nav2 주행 성능을 분포로 측정하고 실패 원인을 분류

## [핵심 개념]
- **왜 반복 측정인가** → 한 번의 주행은 초기 위치·센서 노이즈·타이밍에 좌우, 성능은 분포로 봐야 함
- **핵심 지표**
  - 성공률 $\hat p=\frac{\text{성공 수}}{N}$, 표준오차 $\sqrt{\hat p(1-\hat p)/N}$ → $N$이 작으면 신뢰구간이 넓음
  - 소요시간: 평균보다 분포(중앙값·꼬리) 확인
  - 재계획 횟수: `/plan` 재발행(43강 로거), 리커버리 횟수
  - 충돌·사람 개입 여부
- **시드 고정** → 고정 시드(재현) + 랜덤 시드(일반화)를 함께 써서 비교 가능성 확보
- **초기화의 완전성** → 매 회차 시뮬 장면·로봇 위치·시뮬레이션 시간 소비자·지도·위치 추정·Nav2 상태를 모두 원상복구해야 회차 간 독립
- **실패 원인 분류** → 위치 추정 실패 / 경로 없음 / 충돌 / 시간 초과 등으로 나눠야 튜닝 방향 결정 가능
- **회귀 게이트(44강)** → 이 러너의 집계 결과가 튜닝 채택 판단의 근거

## [파일별 내용]
- `01_bench_runner.ipynb` — `bench_runner.py` 개요(주석만, 구현 없음)
  1. Isaac Sim USD 장면·로봇 스폰 초기화(고정/랜덤 시드)
  2. 시뮬레이션 시간 소비자 초기화, cuVSLAM 지도 로드, 위치 힌트 제공(42강)
  3. 위치 추정·TF 확인 → nvblox 상태 복원(41강) → Nav2 활성화(43강)
  4. rosbag·로거와 함께 순찰 실행 → 충돌·개입·시간·도달 목표 수 채점
  5. 회차 결과 저장 → 분포와 실패 원인 집계
  - 빠진 맥락: 각 단계의 실제 호출 코드, 채점 기준값, 집계 형식

## [확인 포인트]
- 기대 결과: 회차별 결과 파일 + 성공률·소요시간·재계획 분포와 실패 원인 표
- 흔한 실수: 회차 사이 초기화 누락(이전 costmap·TF 잔존), 시뮬 시간 리셋 후 노드가 시간 역행으로 오동작, 표본 수가 너무 적음
- 점검 질문
  - 성공률 90%와 95%를 구분하려면 대략 몇 회 반복이 필요한가?
  - 위치 추정 실패로 인한 실패를 Nav2 실패와 어떻게 분리해 집계하는가?
  - 고정 시드와 랜덤 시드 결과가 크게 다르면 무엇을 의미하는가?
