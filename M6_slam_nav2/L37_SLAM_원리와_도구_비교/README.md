# [37강. SLAM 원리와 도구 비교 (Cartographer·slam_toolbox·cuVSLAM)]
- 모듈: ⑥ SLAM 및 Nav2 자율주행
- 한 줄 요약: 지도와 위치를 **동시에** 추정하는 닭-달걀 문제(SLAM)를 오도메트리 + 스캔의 결합, 점유 격자, 스캔 매칭, 그래프 최적화의 구조로 이해하고, 2D LiDAR 도구와 이번 실습의 카메라 기반 cuVSLAM·nvblox를 용도로 비교
- ※ 교안에 코드 블록이 없는 이론 강의 → 이 폴더는 요약만 담음

## [필수 이해 기준 (교안 기준)]
- **필수 ①** SLAM이 왜 "닭-달걀 문제"인지, 오도메트리와 스캔이 서로의 **어떤 약점을 메우는지** 설명
- **필수 ②** **점유 격자 지도**의 세 값(비어 있음·점유·미지)과 해상도의 의미
- **필수 ③** **스캔 매칭** = "스캔을 지도에 가장 잘 겹치는 위치 찾기"임을 설명
- 심화: 2D/3D 지도 표현, 그래프 최적화 — 알고리즘 구현이 아니라 구조 이해가 목표 / 2D LiDAR는 비교 이론, 41강은 카메라 기반 cuVSLAM·nvblox로 실행

## [핵심 개념]
- **SLAM (Simultaneous Localization and Mapping)**
  - 위치를 알려면 지도가 필요, 지도를 그리려면(벽을 어디에 그릴지) 위치가 필요 → 둘을 동시에 추정
  - 예: 로봇청소기가 처음 온 집을 그려 냄 / 모듈 ⑥의 첫 질문 "나는 지금 어디에 있는가?"
- **재료와 약점**
  - 2D LiDAR: 회전 레이저의 각도별 거리, 한 바퀴 = 스캔 하나(예: 360개, 10 Hz), `sensor_msgs/LaserScan`
  - 오도메트리: 바퀴 엔코더 회전 적분 → 출발점 기준 위치, 바퀴 미끄러짐·지름 오차가 **누적(드리프트)** — 14강 속도 적분 드리프트와 같은 병
  - 정사각 경로 예: 모퉁이마다 회전 오차가 쌓여 시작점에 돌아와도 추정은 딴 곳
  - **오도메트리 = 연속적이지만 누적 오차 / 스캔 = 순간 형상은 정확하지만 위치 무지** → 서로의 약점을 메우는 결합
- **점유 격자(occupancy grid)** — 2D SLAM 표준 지도
  - 공간을 셀(예: 5 cm)로 나누고 셀마다 점유 확률

  | 값 | 의미 | 색(관례) |
  |---|---|---|
  | ~0 | 비어 있음 (통과 가능) | 흰색 |
  | ~1 | 점유 (벽·장애물) | 검정 |
  | 0.5 | 미지 (관측 안 됨) | 회색 |

  - 갱신 규칙(ray casting): 레이저가 **닿은 셀 = 점유 증거**, **지나간 셀 = 빈 증거**
  - 증거를 로그 오즈로 누적 → 지나가는 사람 같은 일시 관측은 씻겨 나가고 벽은 진해짐
  - 해상도: 세밀함 vs 메모리·속도의 균형 — 작을수록 좋은 것은 아님
- **스캔 매칭 — SLAM의 심장 연산**
  - 현상: 오도메트리만으로 그린 지도는 벽이 두세 겹으로 흐릿, SLAM을 켜면 한 겹으로 또렷
  - $(x^*,y^*,\theta^*)=\arg\max_{x,y,\theta}\ \text{일치도}(\text{스캔을 }(x,y,\theta)\text{에 놓았을 때, 지도})$
  - 일치도 = 스캔 점들이 점유 셀과 겹치는 정도, $\arg\max$ = 최댓값이 아니라 **최댓값을 만드는 위치** → 계산 공식이 아니라 탐색 문제의 선언
  - 초기 추측은 오도메트리가 제공 → 전 지도가 아닌 근방만 탐색 (오도메트리도 완전히 무용하진 않음)
  - 27강 ICP와 같은 문제의 2D판 — Cartographer는 상관법+최적화, slam_toolbox는 상관 스캔 매칭
  - slam_toolbox `correlation_search_space_dimension`: 탐색 범위 vs 계산량 (41강 cuVSLAM에는 적용 안 함)
  - **약점**: 긴 복도 — 복도 방향으로 밀어도 일치도가 거의 같음(평평한 목적 함수) → 그 방향 보정 불가, 11강 특이점처럼 "정보 없는 방향" → 특징 없는 환경이 SLAM의 적
- **그래프 SLAM — 전체를 한 번에 최적화**
  - 순차 스캔 매칭만으로는 작은 오차가 여전히 쌓임
  - 노드: 지나온 포즈(키프레임) / 엣지: 포즈 간 구속 — 오도메트리("1 m 전진"), 스캔 매칭("두 스캔이 이렇게 겹침")
  - 최적화: 모든 구속을 가장 잘 만족하는 포즈 배치 = 수천 변수의 최소자승(Lv.1 19강)
  - **루프 폐합(loop closure)** (39강에서 자세히): 같은 장소 재방문 인식 엣지 하나가 쌓인 드리프트를 경로 전체에 되물려 교정 → 이중 벽이 펴짐
  - "지역 보정의 누적" → "전역 일관성의 최적화"로의 도약
- **도구 비교**

  | 구분 | slam_toolbox | Cartographer | cuVSLAM (+nvblox) |
  |---|---|---|---|
  | 계열 | 그래프 SLAM (상관 스캔 매칭) | 그래프 SLAM (서브맵 + 상관법) | 시각(관성) SLAM, NVIDIA GPU |
  | 입력 | 2D LaserScan | 거리 센서·IMU, 2D·3D | 스테레오/멀티카메라·RGB-D·시각 관성 |
  | 산출 | 점유 지도·포즈 그래프, 이어 매핑·직렬화 | 서브맵·궤적 | 6DoF 포즈 + 희소 시각 지도 |
  | ROS2 | 2D Nav2 연동 용이, CPU | 센서·서브맵 설정 필요, CPU | Isaac ROS 5.0 |
  | 용도 | 2D LiDAR 실내 지상 로봇 | 3D LiDAR 매핑 비교 선택지 | **이번 수업 실습** |

  - slam_toolbox는 3D 도구가 아님 / Cartographer 3D는 IMU·센서 동기화·서브맵 설정이 중요
  - 약점 비교: 카메라 방식은 질감 부족·조명·모션 블러·보정 오류 / LiDAR 방식은 기하 구조·가림·거리 센서 특성
  - cuVSLAM 희소 랜드마크는 충돌 회피 지도로 바로 쓰지 않음 → 깊이 + 추정 포즈를 **nvblox**에 넣어 3D TSDF/ESDF·메시와 **Nav2용 2D 슬라이스** 생성
  - 구형/신형 순위가 아니라 **센서·차원·계산 자원·지도 용도**로 선택

## [용어]
- **SLAM vs Localization**: 지도 작성+위치 추정 동시 vs 지도가 이미 있음
- **오도메트리**: 바퀴 회전으로 추정한 이동 — 드리프트 누적, 단독 사용 불가
- **드리프트**: 순간 오차가 아니라 시간에 따라 쌓이는 누적 오차(적분 기반 추정의 숙명)
- **LaserScan**: 각도별 거리 배열 — 위치 정보 없음, 위치는 매칭으로 얻음
- **점유 격자**: 칸마다 점유 확률 — 미지(회색)와 비어 있음(흰색)은 다른 상태
- **해상도**: 한 칸의 실제 크기 [m]
- **스캔 매칭**: 스캔을 지도에 끼워 맞추기 — ICP(27강)의 2D판
- **키프레임**: 그래프 노드로 저장하는 대표 스캔·포즈 — 모든 프레임을 저장하진 않음
- **그래프 SLAM vs 필터**: 포즈=노드, 관측=엣지로 전역 최적화 vs 순차 추정

## [교안의 실습 과제]
- 코드 블록은 없지만 교안이 직접 해 보라고 제시한 과제
1. **드리프트 체감**: "전진 1 m, 좌회전 90°" 4회 경로를 종이에 그리되 회전마다 +3° 오차 누적 → 시작·끝점 어긋남 계산
2. **미니 ray casting**: 20×20 격자·로봇·벽을 만들고 8방향 가상 레이저로 점유 격자 갱신 함수 작성(브레젠험 또는 균일 샘플링), 위치를 옮기며 지도 완성 과정을 이미지 시퀀스로 저장
3. **스캔 매칭 맛보기**: 27강 과제 3의 2D ICP로 지도 점과 틀어진 스캔 정합 → 복도(평행선 두 줄)에서 복도 방향 오차가 교정되지 않음 확인
4. **(심화)** 1차원 로봇 3걸음(각 1 m, 오차) + 시작점 복귀 루프 구속 → 최소자승으로 포즈 4개 추정, 루프 한 줄이 전체를 교정하는 것 확인
