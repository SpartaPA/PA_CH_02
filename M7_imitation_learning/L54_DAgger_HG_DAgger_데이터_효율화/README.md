# [54강. [실습] DAgger/HG-DAgger 데이터 효율화]
- 모듈: ⑦ 로봇 모방학습 및 정책 최적화
- 한 줄 요약: 스크립트 전문가로 정책이 방문한 상태에 정답을 다시 붙이는 DAgger 루프와, 사람이 개입한 구간만 라벨로 쓰는 HG-DAgger를 구현해 BC의 공변량 이동을 줄임

## [핵심 개념]
- **공변량 이동** → BC 정책은 전문가 상태 분포 $d_{\pi^*}$에서만 학습, 실행 시엔 자기 분포 $d_{\pi}$를 방문
  - 작은 실수 → 처음 보는 상태 → 더 큰 실수, 오차 누적 대략 $O(T^2)$
- **DAgger(Dataset Aggregation)** → 반복 라운드
  1. 현재 데이터 $\mathcal D$로 $\pi_i$ 학습
  2. $\pi_i$로 롤아웃해 방문 상태 수집
  3. 전문가가 그 상태에 정답 $a^*=\pi^*(o)$ 라벨
  4. $\mathcal D\leftarrow\mathcal D\cup\{(o,a^*)\}$ (집계)
  - 학습 분포가 정책의 실제 방문 분포에 맞춰짐 → 오차 누적 $O(T)$
- **전문가의 자격** → 시연 궤적 위가 아니라 "어느 상태에서든" 정답을 줄 수 있어야 함 → 스크립트 전문가 필요
- **CLIK(폐루프 역기구학)** → $\dot\theta=J^{+}(\dot x_d+K e)$, 손끝 목표 속도를 관절 명령으로 변환
- **장애물 반발 휴리스틱** → 목표 방향 인력 − 장애물 척력(퍼텐셜 필드 계열)으로 손끝 목표 속도 결정
- **HG-DAgger** → 사람이 위험할 때만 개입, 개입 구간 $(o,a^*)$만 집계 → 라벨 비용 절감·안전성 확보
- **데이터 효율 곡선** → 라운드(누적 라벨 수)별 성공률로 BC 대비 효율 비교

## [파일별 내용]
- `01_expert.ipynb` — `expert.py`의 `expert_action(obs)` 시그니처와 docstring만
  - 동작: 목표 방향 속도 − 장애물 척력 → IK(CLIK) → 관절 델타(행동)
  - 빠진 맥락: 본문 구현, 이득·척력 반경 등 파라미터
- `02_dagger.ipynb` — `dagger.py` 루프
  - `D = load("demos_clean.hdf5")`: 50강 초기 시연
  - 라운드마다 `train_bc(D)`(51강) → `rollout_collect(pi, n_episodes=20)` → `expert_action`으로 재라벨 → `D = D + labels` → `eval_report(pi, round)`(53강)
  - 주의: `round`는 Python 내장 함수 이름을 가림, `R`·`load`·`rollout_collect` 정의 생략
- `03_hg_dagger.ipynb` — `hg_dagger.py` 설계 주석만
  - 개입 이벤트: (시작 t, 종료 t, 구간 $(o,a^*)$ 목록)
  - 라운드: 정책 실행 20 에피소드 감독 → 개입 데이터 집계 → 재학습 → 반복

## [선수 지식·연결]
- 모듈 ②(11·14강): Jacobian·의사역행렬·DLS → CLIK 전문가의 기반
- 49강: 공변량 이동 이론, 50강: 초기 데이터, 51강: `train_bc`, 53강: `eval_report`
- 모듈 ⑧: 시뮬에서 학습한 정책의 실물 이전으로 이어짐

## [실행 전 준비]

- HG-DAgger: 실시간 개입 입력 장치(마우스 등)와 정책/사람 제어 전환 로직

## [확인 포인트]
- 기대 결과: 라운드가 늘수록 성공률 상승 곡선, 같은 라벨 수에서 BC보다 높은 성공률
- 흔한 실수: 정규화 통계를 라운드마다 갱신하지 않음, 전문가가 장애물 근처에서 불안정, 롤아웃 상태 대신 전문가 궤적을 라벨
- 점검 질문
  - DAgger에서 롤아웃 행동은 정책 것인데 라벨은 왜 전문가 것인가?
  - HG-DAgger가 DAgger보다 라벨 수를 줄이는 대신 잃는 것은?
  - 특이점 근처에서 CLIK 전문가 라벨이 이상하면 어떻게 고칠 것인가?
