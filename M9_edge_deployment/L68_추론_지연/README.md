# [68강. [실습] 추론 지연(P50/P99)·메모리/전력 프로파일링]
- 모듈: ⑨ 에지 컴퓨팅 및 실시간 배포
- 한 줄 요약: 캡처·전처리·추론·후처리 구간별로 지연을 기록해 평균이 아닌 분포(P50/P99)로 파악하고, 지연 예산 대비 병목을 찾음

## [핵심 개념]
- **구간 분해**
  - 전체 지연 $T=T_{capture}+T_{pre}+T_{infer}+T_{post}$
  - 추론만 빨라져도 전처리·캡처가 병목이면 효과 없음 → 구간별 측정 필수
- **분포 지표**
  - P50(중앙값): 평상시 성능
  - P99: 100번 중 1번 넘는 꼬리 지연 → 제어 주기 deadline miss와 직결
  - 평균은 꼬리를 가림 → 제어 안정성은 꼬리 지연이 결정
- **측정이 지연을 만들지 않게**
  - 측정값을 사전 할당 배열에 기록(루프 중 리스트 append·로그 출력·메모리 할당 회피)
  - 단조 시계(`time.perf_counter_ns` 등) 사용
- **GPU 비동기성**
  - GPU 작업은 비동기 → 호스트 시계로만 재면 커널 실행 전에 측정 종료 가능
  - 동기화하거나 CUDA 이벤트로 계측(69강 노드)
- **예산표와의 대조**
  - 66강에서 정한 구간별 예산과 측정치를 비교해 초과 구간 식별
- **메모리·전력**
  - 엔진·버퍼 메모리 사용량, 전력 모드별 지연 차이
  - Jetson에서는 온도 스로틀링으로 장시간 실행 시 꼬리 지연 증가 가능(루트 README 기준)

## [파일별 내용]
- `01_profiler.ipynb` — 원본 `profiler.py`의 측정점 배치
  - `with Timer("capture"): frame = cam.read()`
  - `with Timer("pre"): x = preprocess(frame)`
  - `with Timer("infer"): y = engine.run(x)`
  - `with Timer("post"): out = postprocess(y)`
  - `Timer`: 컨텍스트 매니저, 진입·종료 시각 차이를 구간 이름별 사전 할당 배열에 기록
  - 빠진 맥락: `Timer` 구현, 반복 루프, 백분위 계산(`np.percentile(arr, [50, 99])`), 결과 저장(perf sheet)
  - 주의: `engine.run`이 비동기라면 `"infer"` 구간 종료 전에 동기화 필요
