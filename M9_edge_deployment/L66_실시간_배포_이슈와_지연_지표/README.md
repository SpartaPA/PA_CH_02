# [66강. 실시간 배포 이슈(Jitter·Deadline Miss)와 지연 지표(P50/P99)]
- 모듈: ⑨ 에지 컴퓨팅 및 실시간 배포
- 한 줄 요약: 리눅스+GPU 추론 루프의 실시간성은 **평균이 아니라 꼬리(P99)** 로 결정 — 구간별 지연 예산, 꼬리의 원인 분해, 커널·응용·정책 3층 처방, 그리고 **미스를 전제한 설계**
- ※ 교안에 코드 블록이 없는 이론 강의 → 이 폴더는 요약만 담음

## [필수 이해 기준 (교안 기준)]
- **필수 ①** 추론이 포함된 루프의 **지연 예산표**를 구간별로 세움
- **필수 ②** **P99(꼬리) 기준으로 마감을 설계**해야 하는 이유 설명
- **필수 ③** 마감을 놓쳤을 때의 정책(늦은 결과를 버릴지 쓸지) 결정
- 심화(선택): 꼬리 원인(GC·스케줄링·메모리·열) 추적, 커널 수준 처방 — Lv.1 2강 실시간 등급(Hard/Firm/Soft)을 실제 스펙으로

## [핵심 개념]
- **어디까지 보장할 수 있는가**
  - 실시간 = 빠름이 아니라 **마감 보장** (Lv.1 2강)
  - 리눅스·GPU는 본질적으로 보장 없는 세계 → Hard 실시간 불가
  - 로봇 추론 루프는 대개 **Firm/Soft**면 충분: "P99 < 45 ms, 미스는 드물게, 미스 시 안전한 정책" → 공학으로 도달 가능
- **추론이 낀 루프의 지연 예산**
  - 전형 루프: 카메라 → 전처리 → 추론 → 후처리 → 계획/제어 → 액추에이터
  - $\sum_{\text{구간}}\text{지연}_{P99}\le\text{마감}$ (20 Hz → 마감 50 ms)
  - 예산표 예 (20 Hz)

  | 구간 | P50 [ms] | P99 [ms] |
  |---|---|---|
  | 캡처 | 5 | — |
  | 전처리 | 3 | — |
  | 추론 | 12 | **28** |
  | 후처리 | 2 | — |
  | 제어 | 4 | — |
  | 통신 | 3 | — |
  | **합계 (여유)** | 29 (21) | **45 (5)** |

  - 마감을 어기는 건 평균 프레임이 아니라 **드물게 느린 그 한 번** → 예산은 꼬리로
  - 실제 안전 마진은 P99 기준 여유 5 ms
  - 구간별 P99를 따로 재야 어디를 고칠지 보임 → 측정점(스탬프 위치)이 68강 계측 설계도
- **미스 등급과 올바른 스펙**
  - 대개 **Firm**(늦은 결과는 무가치 — 버리고 다음) 또는 Soft
  - "미스 제로"가 아니라 **"미스율 목표 + 미스 시 정책"** 이 올바른 스펙 (69강 지표: miss rate)
- **꼬리의 병인학 — P50 12 ms, P99 28 ms의 16 ms는 어디서?**

  | 용의자 | 메커니즘 | 서명 |
  |---|---|---|
  | OS 스케줄링 | 다른 프로세스에 CPU 뺏김 | 미스가 부하와 상관, 무작위 산발 |
  | 파이썬 GC | 주기적 쓰레기 수집 정지 | 주기적 스파이크 |
  | 메모리 할당 | 런타임 malloc/페이지 폴트 | 초기·간헐 스파이크 |
  | GPU 경쟁 | 다른 추론/렌더와 큐 경합 | 동시 실행 시 악화, 노드 기동 순간 군집 |
  | 전력·열(65강) | 클럭 다운 | 온도와 동조하는 완만한 상승 |
  | 인터럽트·IRQ | NIC 등 인터럽트 폭주 | 특정 코어만 |

  - **꼬리는 하나의 원인이 아니라 합창** → 서명으로 용의자를 가리고 하나씩 제거(68강 프로파일링)
- **처방 ① 커널 — RT 커널과 우선순위 스케줄링**
  - **PREEMPT_RT**: 커널 선점 가능 → 커널 지연 ms → 수십 µs 수준, Hard는 아니지만 꼬리를 크게 다듬음
  - **SCHED_FIFO**: 제어·추론 스레드에 실시간 우선순위 → 단, 폭주 시 시스템 전체가 굳으므로 **워치독**과 함께
  - **CPU 격리(isolcpus)·코어 고정(affinity)**: 특정 코어를 루프 전용으로 → 스케줄링·IRQ 용의자 제거 (모듈 ① "ISR은 짧게"의 리눅스판)
- **처방 ② 응용 수준의 정석**
  - **할당 없는 핫루프**: 버퍼 사전 할당·재사용, GC 튜닝 또는 핵심 루프 C++/바인딩화
  - **입력은 최신만**(21강 depth=1), **파이프라이닝**: 캡처와 추론을 겹쳐 처리율↑ — 지연 증가는 계측으로 확인
  - **GPU 경쟁 관리**: 스트림 분리·우선순위, 보조 모델 DLA 오프로드(65강 심화)
- **처방 ③ 미스 정책 — 실패를 설계**
  - **버림**(Firm: 낡은 인지로 행동하지 않기)
  - **대체**: 마지막 유효 결과 + 외삽 (35강 예측 유지)
  - **연속 미스 → 안전 상태** (모듈 ① failsafe, 35강 상태 머신)
  - 미스 정책 없는 실시간 설계는 미완성
- **3층 처방의 효과**
  - 기본 → RT+격리: 꼬리 반감 → +응용 정석: P99가 마감 안쪽 → 남는 미스(예: 0.2%)는 미스 정책으로
  - 리눅스 실시간의 정직한 언어 = **"보장"이 아닌 "확률 + 정책"**
- **(심화) 2계층 아키텍처 — 왜 MCU가 여전히 있는가**
  - Edge(리눅스+GPU): "P99 45 ms, 미스 0.2% + 정책"의 Firm 실시간 → 인지·계획
  - MCU: "1 kHz, 지터 µs, 보장"의 Hard 실시간 → 모터 루프와 **최후의 안전**(E-stop·failsafe)
  - Edge가 통째로 죽어도 MCU가 로봇을 안전하게 정지 (8강 failsafe가 아키텍처 원칙)
  - 자율주행 안전 컨트롤러, 휴머노이드 관절 드라이버 등 어디서나 반복

## [용어]
- **지연(latency)**: 입력→출력 시간 — 처리율(throughput)과 다름
- **마감(deadline)**: 반드시 끝내야 하는 시각, 제어 주기가 정함 — 평균이 마감보다 짧아도 미스 가능
- **P50 / P99**: 중앙값 / 상위 1% 경계 — 평균은 꼬리를 숨김
- **꼬리 지연(tail)**: 드물게 나타나는 큰 지연 — 실시간 실패의 주범
- **지연 예산**: 구간별 시간 배분표 — 총합만으론 어디를 고칠지 모름
- **미스율(miss rate)**: 마감을 놓친 비율 — "미스 제로"는 대개 비현실적
- **Firm / Soft 실시간**: 늦으면 무가치 / 가치 감소 — Hard(치명적)와 구분, 미스 정책 결정 기준
- **지터(jitter)**: 지연의 흔들림 — 평균이 같아도 지터가 크면 제어 품질 저하

## [선수 지식·연결]
- Lv.1 2강 실시간 등급, 모듈 ① MCU·failsafe(8강), 21강 depth=1, 34·35강 P50/P95·예측 유지·상태 머신
- 65강: 전력·열 스로틀링, DLA 오프로드 → [L65](../L65_로봇_탑재용_모델_배포_구조/)
- 67강: 변환 실습 → [L67](../L67_ONNX_TensorRT_변환_FP16_INT8_양자화/)
- 68강: 구간별 타임스탬프로 예산표 자동 생성, P50/P99 분포 측정, 꼬리 원인 추적 → [L68](../L68_추론_지연/)
- 69강: 버퍼 사전 할당·최신 슬롯·데이터 나이 기반 deadline·미스 정책(버림/외삽/5연속 HOLD) 구현, 소크 테스트 → [L69](../L69_ROS2_제어_루프_통합_안정성_검증/)

## [교안의 실습 과제]
- 코드 블록은 없지만 교안이 직접 해 보라고 제시한 과제
1. **예산표 작성**: 모듈 ⑩ 시스템(카메라→검출→계획→제어)의 지연 예산표를 P50/P99 두 열로 — 구간별 측정 방법(스탬프 위치) 포함
2. **꼬리 관찰**: 자기 PC에서 간단 추론 루프를 10분 돌리며 지연 기록, 일부러 부하(브라우저 재생·빌드)를 걸어 꼬리가 자라는 것을 히스토그램으로 확인
3. **GC 실험**: 루프 내 리스트 생성(할당) 버전 vs 사전 할당 버전의 지연 분포 비교, `gc.disable()` 효과 관찰 (실험 후 복구)
4. **(심화)** 미스 정책 설계: 모듈 ⑤ 추적 루프에 3단 정책(버림 / 외삽 대체 / 연속 5회 시 HOLD) 명세 작성 → 69강 통합에서 구현

## [확인 포인트]
- 지연 예산을 평균이 아닌 P99로 세워야 하는 이유는? (마감을 어기는 건 드문 느린 한 번)
- 주기적으로 나타나는 지연 스파이크의 유력한 용의자와 응용 수준 처방은? (파이썬 GC → 사전 할당·GC 튜닝)
- SCHED_FIFO의 효과와 위험, 함께 둘 장치는? (중요 작업 우선 / 폭주 시 시스템 정지 / 워치독)
- Firm 루프에서 낡은 결과를 그대로 쓰는 것이 버리는 것보다 나쁜 이유는? (이미 지나간 위치로 행동 — 낡은 인지)
- Edge를 아무리 최적화해도 MCU 계층이 남는 이유는? (Edge는 Firm·확률, MCU는 Hard·보장과 최후 안전)
