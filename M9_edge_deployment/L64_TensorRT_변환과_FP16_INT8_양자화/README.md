# [64강. TensorRT 변환과 FP16/INT8 양자화]
- 모듈: ⑨ 에지 컴퓨팅 및 실시간 배포
- 한 줄 요약: TensorRT가 대상 GPU에 맞춰 **엔진을 굽는** 원리와, 비트를 줄여 속도·메모리·전력을 버는 **양자화**의 조건(캘리브레이션·과제 지표 검증)을 이해 — "FP16으로 2배, 성공률 -0.5%p → 수용" 같은 판단을 계량하는 감각
- ※ 교안에 코드 블록이 없는 이론 강의 → 이 폴더는 요약만 담음

## [필수 이해 기준 (교안 기준)]
- **필수 ①** TensorRT가 하드웨어에 맞춰 **엔진을 굽는다**는 개념과, 엔진이 기기·버전에 종속됨
- **필수 ②** FP32/FP16/INT8의 **속도–정확도 트레이드오프** 설명
- **필수 ③** INT8에 **캘리브레이션 데이터**가 필요한 이유 설명
- 심화(선택): 혼합 정밀도 지정, QAT, 캘리브레이션 방식 비교
- 단, **"정확도 검증 없이 양자화를 적용하지 않는다"** 는 심화가 아닌 필수 원칙

## [핵심 개념]
- **ONNXRuntime vs TensorRT**
  - ORT: "어디서든 잘" / TensorRT: "이 GPU에서 최고로" — NVIDIA GPU(로봇에선 Jetson) 전용
- **TensorRT — 엔진을 "굽는다"**
  - 워크플로우: ONNX → 빌드(대상 GPU에서) → 엔진(`.engine`/`.plan`) → 실행
  - 빌드 단계의 정체
    - 63강 그래프 최적화(융합·상수 접기)를 더 공격적으로, NVIDIA 커널 라이브러리와 결합
    - **커널 자동 튜닝**: 같은 Conv도 구현 전술(타일 크기·알고리즘) 수십 가지 → 대상 GPU에서 **실측**해 최속 선택 (빌드에 수 분 걸리는 이유)
    - 정밀도 지정
  - 결과: 엔진은 **GPU 기종·TRT 버전에 종속** → PC에서 구운 엔진은 Jetson에서 안 돎 → **배포 대상 위에서 빌드**가 원칙
  - 같은 CNN의 지연 사다리 예: PyTorch 12 → ORT(CUDA) 6.5 → TRT FP32 4.1 → FP16 2.0 → INT8 1.2 ms
- **수치 정밀도 — 비트의 경제학**

  | 형식 | 비트 | 메모리 | 상대 속도(전형) | 범위/정밀도 |
  |---|---|---|---|---|
  | FP32 | 32 | 1× | 1× | 기준 |
  | FP16 | 16 | 1/2 | 2~4× | 범위 좁고 정밀도 절반 |
  | INT8 | 8 | 1/4 | 4~8× | 정수 256단계 + 스케일 |

  - 속도 이득의 두 출처: **Tensor Core**(FP16/INT8 행렬곱 전용 하드웨어) + **메모리·대역폭 절감**(63강: 병목은 대역폭)
- **FP16 — 거의 공짜인 반값**
  - 신경망 추론은 FP16으로 대개 충분 (학습도 혼합 정밀도 시대)
  - 범위가 좁아(최대 ~65504) 오버플로 민감 층(큰 로짓·분산 계산)은 그 층만 FP32 유지 → **혼합 정밀도**
- **INT8 — 양자화의 본론**
  - $x\approx s\cdot(q-z),\quad q\in\{-128,\dots,127\}$
    - $x$: 원래 실수값, $q$: 8비트 정수, $s$: 스케일(눈금 폭), $z$: 영점(zero point)
  - 6강 ADC 양자화와 같은 구조 — 연속값을 256개 계단에 배정
  - $s$ 크게: 큰 값은 담기지만 작은 변화가 뭉개짐(해상도 낭비) / $s$ 작게: 세밀하지만 큰 값이 잘림(**포화**)
  - 텐서(또는 채널)마다 실제 활성값 분포를 보고 $s$ 결정 → 이 과정이 **캘리브레이션**
- **PTQ(사후 양자화)와 캘리브레이션**
  - 학습 끝난 모델에 **대표 입력 수백 장**을 흘려 층별 활성값 분포 관찰 → 정보 손실 최소 스케일 선택 (TensorRT 표준 경로, 67강 수행)
  - 롱테일 분포에서
    - 최대값 기준: 꼬리까지 담느라 몸통 해상도 낭비
    - 백분위/엔트로피 기준: 꼬리를 살짝 자르고 몸통을 촘촘히 → 손실 최소
  - **캘리브레이션 데이터 = 배포 분포의 대표** (50강 "데이터가 계약") — 밝은 이미지로만 캘리브레이션한 검출기가 어두운 장면에서 붕괴하는 사고
- **정확도는 어디서 새는가 — 계량 규율**
  - 층별 오차가 아닌 **최종 과제 지표**로 측정: 검출은 mAP(25강), 정책은 성공률(53강 평가기)
  - 민감한 층(첫/끝 층, 어텐션 소프트맥스)은 INT8 제외 → **부분 양자화**
  - 로봇 관점: 박스 1px 흔들림과 제어 행동 흔들림의 비용이 다름 → **과제별 허용선**(예: 성공률 하락 < 1%p) 먼저 정하고 그 안에서 가장 낮은 정밀도 선택
  - 교안 결과표 예
    - YOLO: INT8에서 mAP -0.8%p → 수용
    - BC 정책: FP16 무손실, INT8 성공률 -3%p → **FP16 선택**
    - Diffusion: K회 반복이라 FP16 이득 누적 → 15 → 6 ms
  - "모델마다 답이 다르고, 답은 실측이 정한다"
- **(심화) QAT(Quantization-Aware Training)**
  - 학습 중 가짜 양자화 노드 삽입 → 모델이 8비트 환경에 미리 적응, 손실 크게 회복 / 학습 파이프라인 재실행 비용
  - 판단 순서의 정석: FP16 → PTQ INT8(+부분 양자화) → 부족하면 QAT
  - 그 너머: 4비트·희소화·증류 (LLM 시대에 급발전)

## [용어]
- **TensorRT**: NVIDIA GPU 전용 추론 최적화 엔진 — 학습 프레임워크가 아님
- **엔진 빌드**: 하드웨어에 맞춰 굽는 과정 — 결과물이 기기·버전에 종속, 재사용 불가
- **FP32/FP16/INT8**: 32비트 실수/16비트 실수/8비트 정수 — 비트 감소 시 메모리·대역폭도 절감
- **양자화**: 실수를 정수로 표현 — 그래프 최적화와 달리 정확도가 변함
- **스케일 / 영점**: 눈금 폭 / 0의 위치 — 잘못 정하면 포화·해상도 손실
- **캘리브레이션**: 대표 입력으로 분포 관찰 — 학습이 아닌 통계 수집
- **PTQ / QAT**: 사후 양자화 / 양자화 인지 학습 — QAT는 재학습 필요
- **혼합 정밀도**: 민감한 층만 높은 정밀도 유지 — 정확도 회복의 실무 기법
- **정확도 검증**: 양자화 후 성능 재측정 — 속도만 보고 배포하면 사고

## [선수 지식·연결]

- 65강: 엔진이 올라가는 Jetson(Tensor Core·DLA), 대상 위 빌드 파이프라인 → [L65](../L65_로봇_탑재용_모델_배포_구조/)
- 67강: `trtexec`/Python API로 FP32/FP16/INT8 엔진 빌드, PTQ 캘리브레이션, 정밀도별 결과표 → [L67](../L67_ONNX_TensorRT_변환_FP16_INT8_양자화/) (67강 코드는 대칭 양자화 $[-127,127]$, 영점 $z=0$)
- 68강: 정밀도별 지연 실측 → [L68](../L68_추론_지연/)

## [교안의 실습 과제]
- 코드 블록은 없지만 교안이 직접 해 보라고 제시한 과제
1. **정밀도 사다리 계산**: 자기 GPU(또는 제공 Jetson 수치)에서 51강 CNN의 FP32/FP16 지연을 ORT-CUDA로 측정 → 이론 배수(2×)와 실측 차이 기록 (67강 예열)
2. **양자화 손실 손계산**: 활성값이 $[-0.1,0.1]$에 몰려 있고 이상치 하나가 10.0인 텐서를 최대값 스케일 INT8로 양자화 → 몸통의 유효 단계 수 계산, 백분위 클리핑의 근거를 숫자로
3. **허용선 문서**: 세 모델(검출·BC·DP)의 과제별 정확도 허용선을 근거(실패의 치명도)와 함께 작성 → 67강 판정 기준
4. **(심화)** 혼합 정밀도 설계: Diffusion 정책에서 FP32로 남길 수치 민감 후보 층 지목 → 67강 검증 가설로 기록
