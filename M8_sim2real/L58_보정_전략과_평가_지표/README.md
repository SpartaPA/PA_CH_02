# [58강. 보정 전략(System ID·Fine-tuning)과 평가 지표]
- 모듈: ⑧ Sim2Real 및 가상 물리 시뮬레이션
- 한 줄 요약: 진단(57강) 다음의 처방 — **시뮬을 현실에 맞추는 System ID**와 **정책을 현실에 맞추는 Fine-tuning**을 구분하고, DR까지 합친 3종 무기·학습 곡선 읽기·실패 분석으로 59~62강 워크플로우를 조립
- ※ 교안에 코드 블록이 없는 이론 강의 → 이 폴더는 요약만 담음

## [필수 이해 기준 (교안 기준)]
- **필수 ①** **System ID = 시뮬을 현실에**, **Fine-tuning = 정책을 현실에** 맞추는 두 방향 구분
- **필수 ②** System ID가 57강 진단 실험 오차를 **목적 함수로 승격**한 것임을 설명
- **필수 ③** 보정 전후를 비교할 **평가 지표와 절차** 제시
- 심화(선택): 파라미터 식별 가능성, 소량 실물 데이터 미세조정 전략 → 62강에서 실제 수행, 오늘은 선택 기준

## [핵심 개념]
- **Sim2Real 3종 무기**
  - 견디기(DR, 56강) · 맞추기(System ID) · 적응하기(Fine-tuning)

  | 무기 | 시점 | 하는 일 | 비용 |
  |---|---|---|---|
  | DR | 학습 전 | 분포로 견디기 | 시뮬 계산량 |
  | System ID | 시뮬 보정 | 공칭값 맞추고 잔차로 DR 범위 산정 | 실물 실험 시간 |
  | Fine-tuning | 배포 후 | 실데이터로 마지막 적응 | 실물 시연 수 |

  - 57강 장부의 gap 계열에 따라 배합
- **System ID — 시뮬을 현실에 맞추기**
  - $\xi^*=\arg\min_\xi\sum_{\text{실험}}\left\|s^{real}_{1:T}-\text{Sim}_\xi(s_0,a_{1:T})\right\|^2$
    - $\xi$: 시뮬 파라미터(마찰·감쇠·질량·지연), $s_0$: 같은 초기 상태, $a_{1:T}$: 같은 명령
  - 미지수는 정책이 아니라 **시뮬 파라미터** — 10강 수치적 IK와 같은 구조(오차 줄이는 방향으로 반복 수정)
  - 57강 실험 B(개루프 재생) 오차의 목적 함수 승격 → 진단 도구 = 보정 도구
  - 갭이 줄면 재학습 없이도 정책 성능이 오르는 경우 많음
- **System ID 실무 절차 (62강)**
  1. **여기(勵起) 실험 설계**: 계단(관성·게인), 저속 왕복(마찰·백래시), 자유 낙하/진자(중력항·감쇠) — 6강 $\tau$ 계단 실험이 미니 System ID
  2. **민감도 확인**: 오차에 영향 없는 파라미터는 추정 불가(식별 불가능성, 11강 특이점의 최적화판) — 예: 정지만 하는 실험으론 마찰 불명
  3. **최적화**: 미분 불가 시뮬 → CMA-ES 등 블랙박스 탐색, 간단 모델 → 최소자승(Lv.1 19강)
  4. **검증**: 추정에 안 쓴 궤적으로 재생 오차 확인 (train/val 분리)
  - 산출물 두 가지: 맞춰진 **공칭값** + 잔차가 알려 주는 **불확실성(→ DR 범위 근거)**
- **ID와 DR의 관계**
  - ID가 잘될수록 DR 범위 축소 가능(학습 쉬워짐), ID가 못 잡는 것(접촉의 정성적 차이)은 DR이 견딤
  - **"맞출 수 있는 건 맞추고, 못 맞추는 건 흔든다"**
- **Fine-tuning — 정책을 현실에 맞추기**
  - 실물 시연 소량으로 BC 미세조정: 25강 YOLO·49강 사전학습→FT와 같은 문법, lr 낮게·짧게
  - 실물 HG-DAgger(54강): 시뮬 정책이 운전, 사람이 개입, 개입 데이터로 FT → 가장 실용적인 마무리 공정
  - 주의 ① **파국적 망각**: 실데이터만 맞추다 시뮬 일반성 상실 → 시뮬 데이터 소량 섞기(리허설)
  - 주의 ② **소데이터 과적합**: 수십 개 실데이터에 긴 에폭 → 장면 암기 → 53강 평가기(별도 조건)로 감시
- **평가 지표 — Reward/성공률 곡선 읽기**
  - 네 가지 패턴
    - ① 건강: 단조 상승 후 포화
    - ② 정체: 관측/보상 설계 문제 의심
    - ③ 붕괴: 학습률·랜덤화 폭 과다 (56강 넓은 범위의 증상)
    - ④ **시뮬-평가 괴리**: 훈련 조건 성공률↑, 모의 실물 평가 정체 → 과최적화 신호
  - ④를 보려면 학습 중 주기적으로 **모의 실물 평가를 함께 기록** (53강 평가기가 학습 루프에 상주) — 모듈 표준 관행
  - 병렬 환경(55강)에서는 x축 = **환경-스텝 총량** → 비교 시 축 통일
  - DR 학습 곡선은 원래 출렁임 → 이동 평균 + 분위수 밴드로 표시
- **실패 케이스 분석 (45강 부검의 학습판)**
  - 시뮬의 특권: 실패 에피소드를 전 상태 기록과 함께 무한 재생
  - 절차: 실패 수집 → 클러스터링(초기 조건·랜덤화 파라미터 축) → 대표 사례 재생·부검 → 처방 분기(데이터 추가/랜덤화 조정/보상 수정) → **회귀 시나리오 등록**(44강 게이트)
- **전체 워크플로우 — 나흘의 지도**
  - 59강 태스크 구성·학습 성립 → 60강 DR 학습 + 모의 실물 평가 상주 → 61강 실물(대리) 배포·쌍대 평가 → 62강 gap 진단→ID/FT 보정→재배포
  - 산출물: 태스크 명세 · DR 설정표 · 배포 성적표 · 보정 전후 비교
  - 62강 → 61강 반복 화살표: sim-to-real은 일방통행이 아닌 **순환**
- **(심화) Real-to-Sim**
  - 실물 스캔(31강 클라우드)으로 시뮬 씬 생성, 실물 로그로 시뮬 검증(57강 재생 비교), 실패한 실물 상황을 시뮬에 재현해 집중 학습
  - "디지털 트윈"의 실체 = 이 왕복 순환 (31강 RGBD 스캔=씬, 50강 수집기=로그, ID=검증)

## [용어]
- **System ID**: 시뮬 파라미터를 실물에 맞춰 추정 — 정책을 고치는 것이 아님
- **Fine-tuning**: 실물 데이터로 정책을 조금 더 학습 — 처음부터 재학습과 다름
- **식별 가능성**: 데이터에서 그 값을 알아낼 수 있는가 — 최적화가 수렴해도 값이 무의미할 수 있음
- **파라미터 탐색**: 값을 바꿔 가며 오차 최소화 — 격자·베이지안 등 방법 선택
- **쌍대 평가**: 시뮬과 실물을 같은 잣대로 평가 — 서로 다른 지표면 비교 무의미
- **학습 곡선**: 라운드·에폭별 성능 변화 — 최종값만으론 과정이 안 보임
- **실물 데이터 예산**: 쓸 수 있는 실물 실험 횟수 — 시뮬 대비 비용 수십 배, 실무 최대 제약
- **보정 순서**: 진단 → System ID → Fine-tuning — 순서를 바꾸면 낭비
