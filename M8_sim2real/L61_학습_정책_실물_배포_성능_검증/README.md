# [61강. [실습] 학습 정책 실물 배포·성능 검증]
- 모듈: ⑧ Sim2Real 및 가상 물리 시뮬레이션
- 한 줄 요약: 학습된 DR 정책을 추론 전용 ONNX로 내보내고, 실물 관절 상태를 받아 20 Hz로 관절 목표를 발행하는 ROS2 실행 노드 구조를 이해

## [핵심 개념]
- **추론 전용 내보내기**
  - 학습 그래프(옵티마이저, 가치함수, 탐색 노이즈)를 버리고 정책 순전파만 남김
  - `torch.onnx.export`: 더미 입력으로 그래프를 추적해 프레임워크 독립 파일 생성
  - 모듈 ⑨(63강)의 정식 주제를 미리 사용
- **시뮬과 동일한 관측 파이프라인**
  - 실물 관측은 시뮬 학습 때와 순서·단위·정규화가 완전히 같아야 함
  - 정규화: $\hat o=(o-\mu)/\sigma$, 역정규화: $a=\hat a\cdot\sigma_a+\mu_a$
  - $\mu,\sigma$는 학습 때 저장한 통계(50강 stats)를 그대로 사용
- **실행 노드 처리 순서**
  - obs 조립 → normalize → ONNX 추론 → denormalize → 클램프 → 발행
  - 클램프: 관절 한계·최대 변화량으로 최종 안전 제한
- **고정 주기 제어**
  - `/joint_target`을 20 Hz로 발행 → 시뮬 학습 시의 제어 주기와 일치해야 함
  - 주기 불일치는 정책 입장에서 다른 동역학
- **성능 검증**
  - 실물 성공률을 시뮬·proxy 성공률과 비교 → gap 정량화
  - 실패 사례는 62강 분석 대상

## [파일별 내용]
- `01_내보내기와_실행_노드.ipynb` — 내보내기 한 줄 + 실행 노드 설계 주석
  - `torch.onnx.export(policy, dummy_obs, "dr_policy.onnx")`
    - `policy`: 학습된 정책 `nn.Module`(eval 모드 권장)
    - `dummy_obs`: 실제 관측과 같은 shape·dtype의 더미 텐서
    - 출력: `dr_policy.onnx`
  - 실행 노드는 주석만 존재(코드 없음)
    - 구독 `/joint_states`(실물 $\theta,\dot\theta$), 발행 `/joint_target`(20 Hz)
    - 모듈 ⑤ control 노드의 정책 버전
  - 빠진 맥락: 정책 로드, 입출력 이름 지정, ROS2 노드 클래스, 정규화 통계 로드

## [선수 지식·연결]
- 50강: 관측·행동 정규화 통계 저장
- 59강: 관측 구성 $[\theta,\dot\theta,\text{상대 위치}]$, 관절 델타 행동
- 60강: DR로 학습한 정책이 배포 대상
- 62강: 배포 실패 분석·System ID
- 63강: ONNX/ONNXRuntime 정식 다룸

## [실행 전 준비]
- PyTorch, `onnx`, `onnxruntime`
- ROS 2 + `rclpy`, `sensor_msgs/JointState`
- 실물 로봇(또는 동일 토픽을 내는 모의 환경), 비상정지 준비

## [확인 포인트]
- 기대: 동일 관측 입력에 대해 PyTorch 정책과 ONNX 출력이 수치적으로 일치
- 흔한 실수: 정규화 통계 누락·불일치 → 실물에서 의미 없는 행동
- 흔한 실수: `policy.eval()` 없이 내보내 Dropout/BatchNorm 동작 차이 발생
- 점검 질문
  - 관측 벡터의 원소 순서가 시뮬과 다르면 어떤 증상이 나타나는가?
  - 20 Hz 대신 50 Hz로 발행하면 학습된 관절 델타 행동은 어떻게 해석되는가?
  - 클램프를 정책 출력 후에 두는 이유는?
