# [62강. [실습] 실패 케이스 분석·보정 전략 적용]
- 모듈: ⑧ Sim2Real 및 가상 물리 시뮬레이션
- 한 줄 요약: 실물 로그를 시뮬에서 재생한 오차를 목적 함수로 삼아 물리 파라미터를 추정(System ID)하고, 시뮬을 실물에 맞춰 보정

## [핵심 개념]
- **System Identification**
  - 실물 명령 시퀀스를 시뮬에 그대로 넣고 궤적 비교
  - $\min_\xi\sum_t\|x^{real}_t-x^{sim}_t(\xi)\|^2$ → 실물을 가장 잘 재현하는 파라미터 $\xi$ 추정
  - "실물이 시뮬을 가르친다": DR 분포의 중심을 현실 쪽으로 이동
- **재생 오차(replay error)**
  - 57강에서 정의한 재생 오차를 그대로 목적 함수로 사용
  - 시뮬 실행이 끼어 있어 미분 불가·잡음 섞인 목적 함수
- **무미분 최적화 CMA-ES**
  - 다변량 정규분포에서 후보를 샘플 → 좋은 후보로 평균·공분산 갱신
  - 기울기 없이 동작, 국소 잡음에 비교적 강함
  - 차원이 커질수록 평가 횟수 급증 → 추정 대상 축소 필요
- **추정 대상 선별**
  - 데드존 폭, 지연, 관절 0점 오프셋, 마찰
  - 민감도(재생 오차가 그 파라미터에 반응하는 정도)가 확인된 것만 → 식별 불가능한 파라미터 배제
- **보정 전략**
  - 추정값으로 시뮬 공칭값 수정, 그 주변으로 DR 범위 재설정
  - 이후 소량 실데이터 fine-tuning(루트 README 기준)

## [파일별 내용]
- `01_sysid.ipynb` — 원본 `sysid.py`의 최적화 호출부
  - `minimize(lambda xi: replay_error(xi, real_logs), x0=nominal, method="CMA-ES")`
    - `replay_error(xi, real_logs)`: 파라미터 `xi`로 시뮬 재생 후 실물 로그와의 오차
    - `x0=nominal`: 공칭(설계값) 파라미터에서 시작
  - 주석: 추정 대상(데드존, 지연, 0점 오프셋, 마찰)
  - 주의: `scipy.optimize.minimize`에는 `"CMA-ES"` 메서드가 없음 → 실제로는 `cma` 패키지(`cma.fmin` 등) 같은 별도 구현 필요, 의사코드 수준으로 읽을 것
  - 빠진 맥락: `replay_error` 구현, 로그 로딩, 파라미터 범위(경계) 지정
